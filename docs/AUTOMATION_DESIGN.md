# 업무 자동화 설계

상태: P-01 바로가기와 P-02 로컬 브리지·브라우저 확장을 브랜치에서 구현했습니다(PR 리뷰 대기). 로그인·학교 멤버십 없이 왼쪽 메뉴의 `업무 자동화` 화면을 쓸 수 있고, 브라우저 DOM 자동입력과 감시는 아직 구현하지 않습니다.

## 목표

교사가 School Collect 안에서 반복 업무를 **사용자 정의 버튼**으로 등록하고, 이후 같은 레시피 모델을 이용해 다음 세 가지 유형으로 확장합니다.

1. 바로가기: 나이스, K-에듀파인, 기안, 품의, 출결 등 등록 화면 열기
2. 자동입력: 정형 화면의 필드나 학생 × 날짜 행렬에 앱 데이터를 결정론적으로 입력
3. 감시: 체험학습 신청, 결재 대기 등 목록의 새 항목을 감지해 앱에 알림

AI는 실행 엔진의 필수 구성요소로 두지 않습니다. 자동 입력과 감시는 DOM 규칙과 검증 가능한 레시피를 기본으로 하고, AI는 이후 "레시피 생성 보조"에만 선택적으로 사용할 수 있습니다.

## 1단계: 사용자 정의 바로가기

이번 변경의 범위입니다.

```text
School Collect
  -> 업무 자동화
  -> 버튼 이름 + 대상 URL 등록
  -> 로컬 레시피 저장
  -> 버튼 실행
  -> 기본 브라우저가 등록 URL을 엶
  -> 브라우저에 이미 존재하는 업무포털/SSO 세션 사용
```

### 저장 데이터

현재 레시피는 다음 정보만 보관합니다.

```json
{
  "id": "local-random-id",
  "kind": "shortcut",
  "name": "기안",
  "targetUrl": "https://example.invalid/path"
}
```

실제 학교 URL, 계정, 학생 정보 같은 값은 저장소에 넣지 않습니다. 위 JSON은 구조 설명용이며 실행 가능한 실제 업무 URL이 아닙니다.

레시피는 서버에 업로드하지 않고 Tauri 앱의 사용자별 로컬 설정 디렉터리에 저장합니다.

### 개인 화면과 실행 경계

이 화면은 학교 멤버십이 필요 없는 로컬 화면입니다. 로그인하지 않아도 왼쪽 메뉴에서 열 수 있고, 학교 화면(홈·자료수합·설정)은 같은 셸에서 Permission 상태로 로그인을 안내합니다. 로그아웃해도 등록한 버튼은 그대로 남습니다.

렌더러는 `open_automation_recipe(recipeId)`만 호출합니다. 열 주소는 native가 저장된 레시피를 다시 읽어 결정하고 실행 직전에 한 번 더 검증하므로, 화면에서 임의 URL을 열 수 없습니다.

주소는 `url` crate로 해석합니다. 스킴은 소문자로 정규화되고 기본 포트는 정리되며, 호스트가 없거나(`https://:8080`) `http`/`https`가 아니거나 계정 정보가 포함된 URL은 거부합니다.

저장 파일과 복구 동작:

- `automation-recipes.tsv`에 탭으로 구분해 `id`, `kind`, `name`, `targetUrl`을 기록합니다.
- 저장은 임시 파일에 쓴 뒤 rename으로 교체합니다. 쓰기 도중 중단되어도 기존 파일이 손상되지 않습니다.
- 등록할 수 있는 버튼은 100개까지이며, 파일은 Unix에서 소유자 전용(0600) 권한으로 씁니다. Windows에서는 사용자 프로필 ACL을 따릅니다.
- 읽는 중 형식이 어긋난 행을 만나면 그 행을 `automation-recipes.invalid.tsv`로 옮겨 보관하고 나머지 레시피는 그대로 사용합니다.
- 격리 파일이 512 KiB를 넘으면 복구를 멈추고 원본을 보존한 채 정리 방법을 안내합니다.
- 손상된 행을 격리하기 전에는 원본을 덮어쓰지 않습니다. 조회는 파일을 수정하지 않으므로 격리에 실패해도 남아 있는 레시피를 보여주고 다음 조회에서 다시 시도합니다. 등록/삭제는 격리 성공을 사전 조건으로 요구하며, 격리에 실패하거나 기존 격리 파일을 읽지 못하면 원본과 격리 파일을 그대로 두고 오류를 돌려줍니다.

### 저장하지 않는 것

- 브라우저 쿠키
- 세션 토큰
- 인증서 또는 인증서 비밀번호
- 업무포털 비밀번호
- 학생/보호자 개인정보
- 서버 credential

URL 자체에 basic-auth credential이 포함된 경우 저장을 거부합니다.

## 2단계: 현재 화면 등록용 브라우저 동반 확장

"현재 화면을 기안으로 등록" 기능은 브라우저 확장이 담당합니다. `feat/personal-bridge-extension`에서 아래 구조로 구현했습니다.

```text
School Collect (Tauri)
  <-> 제한된 로컬 브리지 (127.0.0.1:43110)
  <-> Chrome/Edge Extension
  <-> 현재 탭 (제목 + 주소만)
```

확장은 브라우저 프로필의 쿠키 값을 School Collect에 복사하지 않습니다. 현재 탭에서 이미 성립한 로그인 세션을 그대로 사용합니다.

### 브리지 계약

- 주소: `127.0.0.1:43110`에만 bind합니다. 외부 인터페이스로 열지 않습니다.
- 인증: `Authorization: Bearer <token>`. 토큰은 앱이 처음 실행될 때 만들어 `%APPDATA%\kr.schoolcollect.app\automation-bridge.token`(Unix 0600, Windows 사용자 프로필 ACL)에 저장하고 `업무 자동화` 화면에 보여 줍니다. 비교는 상수 시간입니다.
- origin: 브라우저가 `Origin` 헤더를 보내면 고정 확장 ID `dfobjphjganlegjomdgmaaphbjcgpoea`와 정확히 일치해야 합니다. 웹 페이지가 토큰을 알아도 호출할 수 없습니다. `Origin`이 없는 로컬 도구(curl·스크립트)는 토큰만으로 호출할 수 있습니다.
- 엔드포인트:
  - `GET /v1/bridge/status`: 서비스 이름·버전·포트
  - `POST /v1/bridge/shortcuts`: `{ "name": ..., "url": ... }`로 바로가기 레시피 생성
- 거부: http/https 이외 스킴, 자격증명 포함 URL, 빈 이름·80자 초과 이름은 400입니다. 브리지에는 URL 열기, DOM 접근, 임의 JavaScript 실행 경로가 없습니다.
- CORS: 확장 origin만 허용하고 `authorization`, `content-type` 헤더와 GET/POST만 통과시킵니다.

### 확장

- 위치: `apps/extension`. `chrome://extensions`(Edge는 `edge://extensions`)에서 "압축해제된 확장 프로그램을 로드"로 이 폴더를 선택합니다.
- `manifest.json`의 `key`가 확장 ID를 고정하므로 어느 컴퓨터에서 설치해도 ID가 같고 브리지 허용 목록과 일치합니다. `scripts/tests/test_extension_contract.py`가 공개 키에서 ID를 다시 계산해 `bridge.rs`의 상수와 대조합니다.
- 권한은 `activeTab`, `storage`와 `http://127.0.0.1:43110/*`뿐입니다. `cookies`, `<all_urls>`, 광범위 host 권한을 요청하지 않습니다.
- 팝업에서 토큰을 `chrome.storage.local`에 저장하고, `현재 화면 등록`을 누르면 활성 탭의 제목(사용자가 비우면)과 주소를 브리지로 보냅니다. 이름은 80자로 자릅니다.
- 앱 화면의 "브라우저 확장 연결" 카드가 포트·토큰·확장 ID를 보여 줍니다.

### 검증 기록 (2026-09-27, Windows)

- Rust: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings`, `cargo test --workspace --locked`(46개) 통과. 브리지 테스트는 토큰 비교, 토큰·origin 거부, preflight 응답, 레시피 저장, 잘못된 입력 거부, 실제 소켓 응답을 포함합니다.
- 웹: `pnpm --filter @school-collect/app typecheck`·`build` 통과. foundation `python -m unittest discover -s scripts/tests -v`(24개)와 `python scripts/check_repository.py` 통과.
- 실제 소켓 스모크(`curl`): 상태 200, 바로가기 생성 201과 `automation-recipes.tsv` 기록, 자격증명 포함 URL 400, 토큰 없음 401, 다른 origin 403. 스모크로 만든 레시피는 삭제했습니다.
- 실제 Tauri 창: `업무 자동화` 화면에 연결 카드가 포트 43110·토큰·확장 ID로 렌더링되고, 브리지가 만든 버튼이 새로고침 후 "내 업무 버튼"에 나타나는 것을 확인했습니다.
- 실제 브라우저(Edge 154): 임시 프로필로 `--load-extension` 실행 후 확장 페이지가 `chrome-extension://dfobjphjganlegjomdgmaaphbjcgpoea/popup.html`로 열렸습니다. 즉 실제 브라우저가 계산한 확장 ID가 브리지 상수와 일치합니다. 이어서 토큰 저장 -> `연결됨 · school-collect-automation-bridge 0.2.0` -> `현재 화면 등록` -> `'p02-browser-check' 버튼을 등록했습니다.`까지 확인하고, 레시피 파일에 항목이 기록된 것을 대조한 뒤 원래 내용(0바이트)으로 되돌렸습니다. 검증 스크립트는 `.local`(비추적)에 둡니다.
- 남은 한계: 위 검증은 팝업 페이지를 탭으로 열어 수행했고 등록 대상은 브리지 origin(`127.0.0.1:43110`) 페이지였습니다. 도구 모음 아이콘 클릭으로 여는 실제 팝업과 `activeTab` 부여 경로, 실제 업무 사이트 주소 등록은 아직 사람이 직접 확인하지 않았습니다. 또한 현재 Chrome 153은 자동화용 `--load-extension`을 무시해서(확장이 로드되지 않음) 검증은 Edge로 수행했습니다.

## 3단계: 결정론적 자동입력 레시피

자동입력은 좌표 매크로가 아니라 DOM 의미 단위로 구성합니다.

예:

```json
{
  "kind": "table_fill",
  "target": {
    "page": "sports-club-monthly"
  },
  "identity": {
    "rowBy": ["grade", "class", "number", "name"],
    "columnBy": "day"
  },
  "steps": [
    { "op": "find_row" },
    { "op": "find_column" },
    { "op": "focus_intersection" },
    { "op": "set_value", "source": "attendance.status" },
    { "op": "press_key", "key": "Tab" },
    { "op": "set_value", "source": "attendance.note" }
  ],
  "commit": "manual"
}
```

실제 selector와 화면별 식별자는 사용자가 화면을 등록할 때 생성하며 저장소에 하드코딩하지 않습니다.

### 학생 × 날짜 행렬

월별 스포츠클럽/출결과 같은 화면은 아래 순서로 처리합니다.

1. 월/화면 식별
2. 학생 행 식별
3. 날짜 열 식별
4. 교차 셀 포커스
5. 필요한 Tab/Enter 흐름 실행
6. 다음 건으로 이동
7. 입력 결과 재검증
8. 교사가 최종 저장

학생 식별은 이름 하나가 아니라 가능한 경우 학년도/학년/반/번호/이름을 함께 사용합니다.

### 저장 정책

초기 자동입력은 **자동 채우기 + 사용자 검토 + 수동 최종 저장**을 기본값으로 합니다. 출결처럼 영향이 큰 데이터는 저장 버튼 자동 클릭을 별도 권한/설정으로 분리합니다.

## 4단계: 감시 레시피

체험학습 신청처럼 "새 행"을 찾는 기능은 목록의 전체 내용을 서버에 복제하지 않고 이전 상태의 최소 fingerprint와 비교합니다.

예:

```text
체험학습 신청 목록
  -> 신청번호/내부 행 식별자 수집
  -> 이전 fingerprint와 비교
  -> 새 식별자가 있을 때만 알림
  -> 앱에서 "나이스에서 확인" 실행
```

기본 저장값은 새 항목 판별에 필요한 최소 식별자와 마지막 확인 시각입니다. 학생명이나 신청 사유 같은 본문은 알림에 꼭 필요한 경우가 아니면 보관하지 않습니다.

## 5단계: 화면 학습

사용자가 직접 한 번 업무 흐름을 지정합니다.

```text
현재 화면 등록
  -> 이름 지정
  -> 화면 종류 선택
     - 바로가기
     - 자동입력
     - 새 항목 감시
  -> 필요한 필드/표 영역을 클릭
  -> 안정적인 DOM locator 후보 생성
  -> 사용자 확인
  -> 레시피 저장
```

가능하면 다음 순서로 locator를 선택합니다.

1. 안정적인 id/data-* 속성
2. 접근성 role/name
3. label과 input 관계
4. 표 header + row identity
5. 제한된 CSS selector

픽셀 좌표와 "Tab N회"만으로 구성된 레시피는 최후 수단으로 둡니다.

## 실패 안전성

자동화 실행은 다음 조건에서 중단합니다.

- 목표 페이지 식별 실패
- 학생/행이 0개 또는 2개 이상 매칭
- 날짜 열이 모호함
- 예상한 입력 컨트롤이 없음
- 페이지가 로그인 화면으로 바뀜
- 저장 전 검증 결과가 입력 계획과 다름

부분 실패 시 이미 입력한 항목과 실패 항목을 구분해 보여주고 조용히 다음 단계로 진행하지 않습니다.

## 보안 경계

- Tauri 클라이언트는 신뢰 서버가 아닙니다.
- 학교 업무시스템 인증을 School Collect 서버로 프록시하지 않습니다.
- 브라우저 세션을 앱 서버로 전송하지 않습니다.
- 자동화 권한은 "사용자의 현재 로그인 세션에서 사용자가 할 수 있는 동작"을 넘지 않습니다.
- 실제 학교 화면 구조, URL, 캡처, 학생 데이터는 public 저장소/Issue/PR/로그에 넣지 않습니다.
- 화면별 레시피 공유 기능을 만들 경우 selector와 비민감 metadata만 공유하고 사용자 데이터는 분리합니다.

## 현재 미구현 범위

이번 슬라이스는 다음을 아직 하지 않습니다.

- 현재 탭의 DOM 요소·표 영역 캡처(제목·주소 등록만 구현)
- DOM 클릭/입력
- Tab/Enter 매크로 실행
- 스포츠클럽/출결 화면별 adapter
- 체험학습 신규 신청 감시
- 로그인 유지 요청
- 인증서 자동 로그인
- AI 기반 화면 인식

이 기능들은 브라우저 동반 확장과 검증 가능한 레시피 실행기가 먼저 들어온 뒤 추가합니다.

## 후속 개선

### 반영됨 (2026-09-27)

- URL 검증: `url` crate로 호스트 필수, 스킴 정규화, 기본 포트 정리, 계정 정보 거부를 적용했습니다.
- 실행 경계: `open_automation_target(url)`을 `open_automation_recipe(recipeId)`로 바꿔 렌더러가 임의 URL을 열지 못하게 했습니다.
- 브라우저 열기: `rundll32`(Windows)·`open`(macOS)·`xdg-open`(Linux)을 기다리지 않고 분리 실행하고 종료 상태만 수거합니다.
- 레시피 파일: Unix 소유자 전용 0600, 레시피 100개 상한, 격리 파일 512 KiB 상한.
- `decode_recipe`도 값을 trim해 저장·검증 기준과 맞췄습니다.
- 개인 화면을 로그인 없이 열 수 있게 하고, "이 컴퓨터의 사용자 설정에 저장된다"는 범위 안내를 화면에 넣었습니다.
- 삭제는 두 번 눌러 확인하고, 삭제한 버튼은 알림 줄의 `실행 취소`로 같은 id에 되돌릴 수 있습니다. 열기·삭제·확인 버튼에는 버튼 이름이 포함된 `aria-label`을 붙였습니다.

### 남은 항목

- `tauri-plugin-opener` 전환 여부 검토(현재는 OS 기본 명령 분리 실행).
- 레시피 범위는 여전히 School Collect 계정이 아니라 OS 사용자 단위입니다. 계정별 분리는 필요해지면 별도 설계로 다룹니다.

### 네이티브 창 검증 (2026-09-27, Windows)

개발 빌드(`cargo run -p school-collect-app` + Vite dev 서버)를 실제 데스크톱 창에서 조작해 확인했습니다. WebView2 접근성 트리로 UI 요소를 찾아 누르고, 같은 시점의 로컬 레시피 파일 상태를 대조했습니다.

- 로그인하지 않은 상태에서 왼쪽 메뉴의 `업무 자동화`가 열렸고, 학교 화면(`홈`)은 같은 셸에서 `로그인이 필요합니다` Permission 상태로 표시됐습니다.
- `테스트기안`(가상 주소 `https://example.invalid/draft`)을 등록하자 화면에 알림과 목록 항목이 생기고 `automation-recipes.tsv`에 92바이트로 기록됐습니다.
- `열기`를 누르면 `브라우저 열기를 요청했습니다.`가 표시되고 기본 브라우저 열기 프로세스가 시작됐습니다(비동기 실행).
- `삭제` 첫 클릭은 확인 상태만 보여 주고 파일을 건드리지 않았습니다. `삭제 확인`을 누르자 목록이 비고 파일이 0바이트가 됐으며, `실행 취소`로 원래 92바이트 내용이 복원됐습니다.
- 앱을 종료하고 다시 실행해도 목록 항목이 그대로 남아 있었습니다(파일 기준 복원).
- 검증에 쓴 테스트 레시피는 삭제해 파일을 0바이트로 되돌렸습니다. 실제 업무 URL·계정·개인정보는 사용하지 않았습니다.
