## 데이터와 로그인 경계

- 바로가기·레시피는 현재 OS 사용자별 설정 디렉터리의 TSV 파일입니다. 학교 계정·DB에 귀속되지 않습니다.
- School Collect 로그인/학교 선택/로그아웃 때문에 개인 버튼이 숨겨지거나 삭제되지 않아야 합니다. 같은 OS 계정을 함께 쓰는 사람 사이의 분리는 현재 제공하지 않으므로 P-01에서 안내·삭제 정책을 명확히 합니다.
- 브라우저 쿠키·인증서·비밀번호·세션 토큰을 서버로 복사하거나 레시피에 저장하지 않습니다. URL의 자격증명·민감한 query에 대한 등록·로그 정책을 확인합니다.
- 학교 제출 초안은 개인기능 데이터가 아닙니다. 학교 데이터를 쓰는 자동입력은 P-05의 API 권한·보존·정리 정책을 적용합니다.
- 단절 중에도 로컬 버튼 관리가 가능해야 합니다. 외부 사이트 연결 실패와 학교 API 장애를 구분해 표시합니다.

## P-01에서 마무리한 것

아래 항목은 PR #25에서 반영하고 실제 창에서 확인했습니다.

- PR #25와 `c31b9d9`의 개인기능을 비교해 recipe ID 실행 경계와 로그인 없는 진입을 유지했습니다.
- `url` crate로 호스트·scheme·credential을 검증하고 저장 시 표기를 정규화했습니다.
- 브라우저 열기는 기다리지 않고 분리 실행하고, 실패를 오류 문구로 돌려줍니다.
- 레시피 100개·격리 파일 512 KiB 상한과 Unix 0600 권한, 격리 실패 시 원본 보존을 테스트로 확인했습니다. Windows는 사용자 프로필 ACL을 따릅니다.
- 실제 Tauri 창에서 로그인 전 열기 -> 등록 -> 열기 -> 재시작 보존 -> 삭제 -> 실행 취소를 확인했습니다. 학교 화면은 Permission 상태로 남았습니다.

## P-02에서 구현한 것

PR #30(`feat/personal-bridge-extension`)으로 데스크톱 앱의 제한된 로컬 브리지와 Chrome/Edge 확장을 develop에 통합했습니다. 세부 계약과 검증 기록은 [AUTOMATION_DESIGN.md](AUTOMATION_DESIGN.md)의 "2단계"에 있습니다.

- 브리지는 `127.0.0.1:43110`에만 열리고, 짝 맞춘 토큰(`automation-bridge.token`, 64자 hex)과 고정 확장 ID origin을 함께 확인합니다. 토큰은 상수 시간 비교이고, 브라우저가 `Origin`을 보내면 `chrome-extension://dfobjphjganlegjomdgmaaphbjcgpoea`와 정확히 같아야 합니다.
- 브리지가 제공하는 것은 상태 확인과 바로가기 생성뿐입니다. URL 열기, 쿠키·DOM 접근, 임의 JavaScript 실행은 없습니다.
- 확장은 `apps/extension`을 "압축해제된 확장 프로그램"으로 로드해 쓰고, `manifest.json`의 `key`로 ID를 고정합니다. 권한은 `activeTab`·`storage`와 `http://127.0.0.1:43110/*`뿐이고, 등록 값은 현재 탭의 제목과 주소입니다.
- 앱의 `업무 자동화` 화면에는 포트·토큰·확장 ID를 보여 주는 "브라우저 확장 연결" 카드가 있습니다.

검증한 것과 아직 아닌 것:

- 통과: Rust 단위·통합 테스트(워크스페이스 46개), clippy `-D warnings`, 앱 typecheck/build, foundation 24개, repository guard. 실제 소켓 스모크에서 상태 200, 등록 201과 파일 저장, 자격증명 포함 URL 400, 토큰 없음 401, 다른 origin 403을 확인했습니다. 실제 Tauri 창에서 연결 카드 렌더링과 브리지로 만든 버튼이 목록에 나타나는 것도 확인했습니다.
- 통과(실제 브라우저, Edge 154): 확장이 `chrome-extension://dfobjphjganlegjomdgmaaphbjcgpoea/popup.html`로 로드됐고, 토큰 저장 -> 연결 확인 -> 현재 화면 등록까지 성공해 레시피 파일에 기록된 뒤 원래 내용으로 되돌렸습니다. 고정 ID와 매니페스트 권한은 `scripts/tests/test_extension_contract.py`가 공개 키에서 ID를 다시 계산해 브리지 상수와 대조합니다.
- 아직 아님: 도구 모음 아이콘 클릭으로 여는 실제 팝업·`activeTab` 부여 경로와 실제 업무 사이트 주소 등록은 사람이 직접 확인하지 않았습니다. 검증은 팝업 페이지를 탭으로 열어 수행했고 대상은 브리지 origin 페이지였습니다.

## P-03에서 구현한 것

PR #32(저장 형식·요소 선택·미리보기, `feat/personal-fill-recipes`)와 PR #33(실행·결과 검증, `feat/personal-fill-execute`)으로 자동입력 레시피 엔진을 develop에 통합했습니다.

- 레시피 종류가 `shortcut`/`fill`로 나뉘고, 자동입력 레시피는 화면 주소와 필드 목록(이름 + 위치)을 함께 저장합니다. 저장 형식은 기존 4열 TSV에 필드 JSON을 담은 5열을 더한 형태라 이전 파일을 그대로 읽습니다.
- 위치는 `id`, `name`, `label`, `css` 네 종류만 허용합니다. 임의 JavaScript나 자유 형식 XPath는 받지 않고, CSS는 문자 집합과 함수형 선택자(`:has`, `:is` 등)를 제한하며 `nth-child()`/`nth-of-type()`만 허용합니다.
- 확장은 페이지에 고정 명령 함수 하나만 주입합니다(`pick`, `preview`). 브리지와 앱은 데이터만 보내고 코드를 보내지 않습니다.
- 미리보기는 각 필드의 일치 수와 현재 값을 보여 주고, 0개·2개 이상이면 "입력하지 않음"으로 표시합니다.
- 실행은 먼저 모든 필드를 해석해 하나라도 0개·2개 이상이거나 쓸 수 없는 컨트롤이면 **아무것도 입력하지 않고** 중단합니다. 통과하면 값만 넣고 `input`/`change` 이벤트를 보낸 뒤 다시 읽어 검증합니다.
- 값은 실행할 때 확장 팝업에서 입력하며 레시피나 서버에 저장하지 않습니다. 저장 버튼·제출 버튼은 누르지 않고, 사이트에서 사용자가 직접 저장합니다.

검증 기록은 [AUTOMATION_DESIGN.md](AUTOMATION_DESIGN.md)의 3단계 절에 있습니다.

## P-04에서 구현한 것

PR #35(`feat/personal-table-fill`)로 학생 × 날짜 행렬 입력을 develop에 통합했습니다.

- 레시피 종류에 `table_fill`을 추가했습니다. 표 위치와 행 식별 머리글(예: 학년·반·이름), 날짜 열 머리글만 저장하고 열 인덱스는 저장하지 않습니다.
- 저장 형식은 기존 4열 TSV를 유지하고 5번째 열 JSON에 `fields` 또는 `table`을 담습니다. 이전의 필드 배열 형식도 그대로 읽습니다.
- 확장 팝업에서 표 안의 칸을 클릭해 표를 등록하고, 머리글에서 행 식별 열과 날짜 열을 찾아 보여 줍니다. 미리보기는 행 식별 값과 날짜 열의 현재 값을 탭으로 구분한 행렬로 채웁니다.
- 실행은 입력 계획을 모두 세운 뒤에만 쓰고, 칸마다 다시 읽어 `확인`/`검증 실패`를 구분해 표시합니다. 저장·제출 버튼은 누르지 않습니다.
- 중단 조건: 행 식별 값 중복, 저장한 머리글을 지금 표에서 찾지 못함, 입력 칸이 없거나 여러 개, 미리보기 이후 행 식별 변경. 중단 시 아무것도 입력하지 않고 이유를 팝업에 문장으로 표시합니다.
- 값은 P-03과 같이 실행할 때만 페이지로 보내고 레시피·서버에 저장하지 않습니다.

검증은 [AUTOMATION_DESIGN.md](AUTOMATION_DESIGN.md)의 "학생 × 날짜 행렬" 절에 있습니다. 실제 업무 사이트에서의 사람 검증과 월/화면 식별자 확장은 남아 있습니다.

## P-06에서 구현한 것

PR #37(`feat/personal-watch-recipes`)로 새 신청·결재 감시를 develop에 통합했습니다.

- 레시피 종류에 `watch`를 추가했습니다. 목록의 행 위치(css)와 행 안에서 식별자를 읽을 위치만 저장하고, 5번째 열 JSON에 담아 이전 형식을 그대로 읽습니다.
- 확장 팝업에서 행 안의 식별자(예: 신청번호)를 클릭해 감시를 등록하고, `감시 실행`으로 식별자 목록을 브리지(`POST /v1/bridge/watch-scans`)에 보냅니다.
- 앱이 이전 식별자와 비교해 새 항목만 돌려주고, 화면에 `항목 N개 · 마지막 확인 …`과 새 항목 수를 표시합니다. `새 항목 확인`으로 알림을 지우고 `감시 중지`/`감시 다시 켜기`로 상태를 관리합니다.
- 감시 상태(`automation-watch-state.json`)에는 식별자와 확인 시각만 저장합니다. 학생 이름·신청 사유 같은 본문은 읽지도 저장하지도 않습니다.
- 중단·억제: 이미 본 식별자는 다시 알리지 않고, 중지 중에는 상태를 바꾸지 않으며, 행 없음과 로그인 화면을 구분하고, 식별자가 중복되거나 하나로 특정되지 않으면 저장하지 않습니다. 레시피를 지우면 감시 상태도 함께 정리합니다.
- 확인은 사용자가 확장 팝업에서 실행합니다. 백그라운드 자동 확인은 대상 사이트 host 권한을 상시로 요구하므로 별도 결정이 필요합니다.

검증은 [AUTOMATION_DESIGN.md](AUTOMATION_DESIGN.md)의 4단계 절에 있습니다.

## 확장·실행 원칙

Tauri <-> 제한된 로컬 브리지 <-> Chrome/Edge 확장 <-> 현재 탭을 기본 방향으로 둡니다. 임의 JavaScript 문자열 실행 없이 명시적인 recipe ID와 정해진 명령만 처리합니다. locator는 안정적인 속성, 접근성 role/name, label, 표 header/row identity를 우선합니다.

사용자가 필드·표 영역을 지정하고 생성된 locator를 확인해 레시피를 저장합니다. 로그인 화면 전환, 행/열/컨트롤의 0개·복수 매칭 시 중단하고 완료·실패 건을 구분합니다. 입력 결과를 검증한 뒤 최종 저장은 사용자가 수행하며 영향이 큰 데이터의 자동 저장은 별도 권한·설정으로 둡니다.

감시에는 최소 식별자·마지막 확인 시각만 보관하고 학생명·신청 사유 등 본문은 기본 저장하지 않습니다. 실제 업무 URL·화면 캡처·학생 데이터·레시피 원본을 public 저장소나 PR에 넣지 않습니다.

## 변경 책임과 배포

P-01은 `apps/app`의 개인 화면·레시피 클라이언트·native adapter를 소유합니다. P-02에서 확장·브리지 경로를 `apps/extension`(확장)과 `apps/app/src-tauri/src/bridge.rs`(브리지)로 확정했습니다. `packages/ui`는 C-01과 조율하고 학교 domain/DB/API는 P-05의 명시적 계약이 필요한 경우에만 변경합니다.

개인기능은 해당 범위의 native 동작·로컬 복구·권한을 검증합니다. 학교 서버 배포·학교 초대·R2/NATS 구축 때문에 순수 로컬 기능 개발을 보류하지 않습니다.
